# توضیحات پروژه

## تا کجا پیش رفتم

پروژه رو تا سطح Advanced جلو بردم و تمومش کردم. یعنی هر سه بخش Core و Standard و Advanced پیاده‌سازی شدن و همه چیز تست شده.

خلاصه‌ی هر سطح:

- **Core:** کلاس‌های پایه، تست کیس، و منوی کنسول با ۹ گزینه.
- **Standard:** گزارش‌گیری شهری (تعداد و مبلغ کل پرداختی هر شهر) و منوی جدا برای Admin و User.
- **Advanced:** حذف کاربر و پالیسی، تغییر رمز ادمین، تولید خودکار ID با counter استاتیک، و گزارش‌گیری مدل خودرو (تعداد، مبلغ کل و میانگین).

هر بخش هم توی UI منوی خودشو داره و بعد از هر عملیات، پیام "press any key to continue" نمایش داده میشه.

---

## چطور پیاده‌سازی کردم

پروژه از ۹ کلاس اصلی تشکیل شده: `Address`، `Car`، `CarType`، `MyDate`، `InsurancePolicy` (abstract)، `ThirdPartyPolicy`، `ComprehensivePolicy`، `User` و `InsuranceCompany`.

چند نکته‌ی مهم توی طراحی:

- **وراثت:** `ThirdPartyPolicy` و `ComprehensivePolicy` از `InsurancePolicy` ارث می‌برن و متد `calcPayment` رو با فرمول خودشون پیاده‌سازی می‌کنن.
- **تجمیع:** `InsuranceCompany` یه لیست از `User`ها داره و هر `User` هم لیستی از پالیسی‌ها و یه `Address`.
- **کپسوله‌سازی:** همه فیلدها private یا protected هستن و از طریق getter/setter بهشون دسترسی داریم.
- **تولید ID خودکار:** هم `User` و هم `InsurancePolicy` یه `static int idCounter` دارن که توی سازنده increment می‌شه. اینطوری نیازی نیست ID رو از بیرون بگیریم.

برای اینکه منطق برنامه از UI جدا بمونه، متدهای مربوط به تعامل با کاربر رو توی `UiMethods` گذاشتم و `Ui` فقط منوها و مسیردهی رو مدیریت می‌کنه.

## درباره تست کیس

یه فایل اکسل به اسم `test-case.xlsx` آماده کردم که ۶۰ تا تست توش هست. برای هر تست این ستون‌ها پر شده: `Test ID`، `Class`، `Test explanation`، `Expected`، `Actual`، `Status` و `Justification`.

تست‌ها به ترتیب سطح چیده شدن (از Core تا Advanced) و همه متدهای مهم کلاس‌ها رو صدا می‌زنن. خروجی واقعی رو از اجرای `TestCode.runTests()` گرفتم و با مقدار Expected مقایسه کردم. خوشبختانه همه تست‌ها PASS شدن.

توی ستون Justification هم دلیل منطقی هر تست رو نوشتم (مثلاً فرمول محاسبه یا شرط اعتبارسنجی) تا مشخص باشه چرا اون عدد یا رفتار درسته.

## یه تغییر کوچیک نسبت به تکلیف

توی متدهای گزارش مدل خودرو (`getTotalPaymentForCarModel` و `getTotalPaymentPerCarModel`) یه پارامتر اضافه به اسم `flatRate` گذاشتم. دلیلش این بود که محاسبه حق بیمه به نرخ ثابت شرکت وابسته‌ست. اگه این مقدار پاس داده نشه، مبلغ با نرخ صفر حساب می‌شه و با گزارش شهری هماهنگ نمی‌مونه.

با این تغییر، همه گزارش‌ها از یه نرخ واحد استفاده می‌کنن و خروجی‌ها دقیق‌تر و قابل مقایسه‌تر شدن.

## نکته درباره باگ Car در TestCode
توی TestCode، چند پالیسی به صورت عمدی به یک شیء Car مشترک اشاره میکنن. این باعث میشه وقتی carPriceRiseAll صدا زده می‌شه، برای هر پالیسی یه بار priceRise اجرا بشه و چون همه به یه خودرو اشاره می‌کنن، قیمت چند بار بالا بره.

مثلاً توی تست TC-28، قیمت BMW از 143000 به 157657.5 میرسه (دو بار افزایش 5%)، در حالی که اگه هر پالیسی خودروی مستقل داشت، فقط یه بار افزایش پیدا میکرد و به 150150 می‌رسید.

این رفتار باگ نیست، بلکه یه سناریوی عمدی برای تست متد carPriceRiseAll و بررسی رفتار اشتراک شیء توی جاواست. اگه نیاز باشه، می‌شه با ساخت new Car(...) برای هر پالیسی، این اثر رو حذف کرد.

## جمع‌بندی

پروژه تا آخر (Advanced) پیاده‌سازی شده، UI هر سه سطح کار میکنه، تست کیس کامل نوشته شده و همه متدها هم پوشش داده شدن.
